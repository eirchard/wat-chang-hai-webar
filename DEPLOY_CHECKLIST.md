# Deployment checklist — CAHAYA WebAR

The source pages have been uploaded. **Image tracking is not yet complete.** Before scanning the printed poster, these binary assets must exist:

- `assets/target-wat-chang-hai.jpg` — upload the ORIGINAL poster image supplied to ChatGPT.
- `assets/targets.mind` — use https://hiukim.github.io/mind-ar-js-doc/tools/compile/ to compile the same image.
- `assets/wat-chang-hai-stupa.glb` — a demo model can be generated by the GitHub Actions workflow *Build demo 3D model* (requires Actions write permission).

The model is a stylized demo, not a faithful 3D reconstruction of the real temple.

### GitHub Pages

Open Settings → Pages → Build and deployment → Source: **GitHub Actions**, then open Actions to see the *Deploy WebAR to GitHub Pages* workflow. 

Viewer: https://eirchard.github.io/wat-chang-hai-webar/
3D preview: https://eirchard.github.io/wat-chang-hai-webar/preview.html

If the build-model workflow cannot commit the generated GLB, go to Settings → Actions → General → Workflow permissions and choose Read and write permissions (if available), then rerun the model workflow.

The WebAR viewer requires HTTPS, camera permission, a matching .mind target, and a GLB asset. Do not use the public AR viewer for an exhibition before testing on actual phones.
